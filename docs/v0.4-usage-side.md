# v0.4 用量侧对齐批次 — 详细规格

> 原则：页面、按钮、字体、布局全部向 TokenTracker 靠（其 dashboard 为 MIT，可直接移植组件，文件头注明来源）。
> 实景参照：TokenTracker 已在本 VPS 运行（:7680），五个目标页截图已核对，规格按实物写。
> 范围（用户定）：常规用量、会话、限额、Skills、设置。云端账号相关推迟到 v0.3。

## 0. 前端技术栈切换（本批次的前置工程）

现状是单文件内联 HTML；对齐 TokenTracker 需要真正的前端工程：

- ⬜ `dashboard/` 迁移为 **React 18 + Vite + Tailwind**（与上游同栈，组件可直接搬）
- ⬜ 移植设计基建：`tailwind.config.cjs` 的 oai 字体族（'OpenAI Sans' 栈）、oai-gray 色板、display 字号（72px hero 数字）、`darkMode: "class"`；`styles.css` 的 CSS 变量
- ⬜ 布局骨架：左侧边栏（GENERAL / TOOLS / ACCOUNT 分组，底部主题切换 + GitHub star 按钮）+ 右侧圆角白卡内容区
- ⬜ 构建产物 `dashboard/dist` 由 `usageplane serve` 静态托管（沿用现有 server）
- 移植候选组件（上游 `dashboard/src/ui/dashboard/components/`）：`StatsPanel`、`ActivityHeatmap`、`UsageOverview`、`DataDetails`、`ProviderIcon`、`DateRangePopover`、`UsageLimitsPanel`

## 1. 常规用量页（Tokens，即首页）— 对照上游 DashboardPage.jsx (1445 行)

实景要素（按重要性排序）：

- 时间范围切换：Day / Week / Month / Total / Custom 胶囊组，右上 Share + 刷新
- Hero 区：TOTAL TOKENS 大数字（72px）+ 绿色成本估算 `$455.03 ⓘ`
- 工具占比卡：All / CLAUDE / CODEX… 各占比 + 模型数
- Daily Breakdown 表：Date / Total / Input / Output / Cached / Reasoning / Convs，可切 Project Usage 视图
- 左栏：7d/30d/avg/convs 四统计 + 模型占比排名 + Started/Active days
- Activity Heatmap：GitHub 风格年度格子（2D/3D 切换、时区标注）
- 保留我们独有的"中转站资产"侧卡（FEATURE-MAP 缝合价值），放右栏下方

后端需求：

- ⬜ `/api/usage?range=day|week|month|total|custom`：按桶聚合出 hero、占比、daily 表（store 已有数据，加聚合查询）
- ⬜ **成本估算**：移植上游定价表（`src/lib/pricing/curated-overrides.json` + `computeRowCost` 语义——成本永不从 total_tokens 算）；estimated 口径标注，与中转站 reported 永不相加
- ⬜ 热力图数据：`/api/heatmap`（按日 total，一年窗口）

## 2. 会话页（Sessions）— 对照上游 SessionsPage.jsx (542 行)

实景要素：

- 标题下副标语；筛选行：工具胶囊（All/Claude Code/Codex）+ 时间（All/7d/30d/90d）+ 项目下拉 + 搜索框 + 计数
- 列表行：模型图标 + 会话标题（取首条用户消息/summary）+ 项目 · 模型 · 时间 · 时长 | 右侧 Tokens / Cost / Turns / Edits 四列 + **Copy command**（复制 `claude --resume <sessionId>`）

后端需求：

- ⬜ `/api/sessions`：扫描 `~/.claude/projects` 会话 JSONL 提取元数据（标题、项目、模型、起止时间、turns、edits、token 合计、成本估算、session id）。移植参照上游 `src/commands/sessions.js` 与 local-api 对应端点
- Codex 会话（rollout 文件）同列表混排，resume 命令为 `codex resume <id>`

## 3. 限额页（Limits）— 对照上游 LimitsPage.jsx + usage-limits.js

实景要素：

- 每个 provider 一块：图标 + 名称；已连接的显示进度条组（Claude Max：5h 窗口 46%·4m 重置，7d 12%·5d，Opus/Fable 独立条 20%·5d），未连接显示 "Not connected"
- 右上：通知开关 + 设置齿轮

后端需求：

- ⬜ Claude 限额：`GET https://api.anthropic.com/api/oauth/usage`（header `anthropic-beta: oauth-2025-04-20`），OAuth token 读本机 `~/.claude/.credentials.json`（macOS 走 keychain——远期）。**必须移植上游的缓存与 429 退避**（`claude-usage-limits-cache.json` + `retry-after` 持久化——Claude 的 OAuth 端点和 Claude Code 本体共享配额，打爆会影响用户正常使用，这是上游注释里的血泪教训）
- Codex/其他 provider 限额：v0.4 先 "Not connected" 占位，Windows 数据通了再逐个接
- ⬜ 多设备语义（我们独有）：hub 聚合下限额按设备标注（VPS 的 Max 订阅 ≠ Windows 的）

## 4. Skills 页 — 对照上游 SkillsPage.jsx (1818 行)

## 验收（整批）

1. 五页与 TokenTracker 同屏对比（VPS 上两者并跑，:7680 vs :7690），布局/字体/间距肉眼无重大偏差；浅/深色各截一轮
2. 首页数字与 `usageplane status` 一致；成本估算与 TokenTracker 同数据误差可解释（定价表版本差异要能指出来）
3. Sessions 的 Copy command 能真实 resume 对应会话
4. Limits 的 Claude Max 数字与 TokenTracker 同屏一致
5. 全程沿用既有铁律：estimated/reported 分离、来源不猜测、隐私（会话标题属于内容边缘——**标题只在本机页面展示，绝不进 hub 上传**，需在 push 路径加保护并测试）

## 排序建议（依赖关系）

栈迁移+设计基建 → 常规用量页（背靠现有数据，最快见效）→ Sessions → Settings/Appearance → Skills → Limits（外部 API 风险最高，放最后）
