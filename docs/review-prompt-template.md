# 阶段审查提示词模板

每批交付后，按此模板生成审查提示词交给独立审查方（Codex/GPT）在 Windows 侧执行。
`{…}` 为每次填充的占位符；校准规则段落原样保留，不随批次变化。

来历：多轮审计后的校准决策（2026-08-08，见 CLAUDE.md「审计项校准」与 ROADMAP 决策日志）——
审查方必须先对照上游源码再定级，终止"按上游自己都不满足的基准打 P1"的循环。

---

````markdown
# UsagePlane 阶段审查：{阶段名称}

## 角色与范围
你是本仓库的独立审查员。仓库在 {Windows 仓库路径}，
本阶段待验收提交：
{commit 列表，一行一个：hash + 标题；注明哪些是 docs 仅浏览}

只读审查 + 隔离环境实测。不修改仓库代码；临时产物放独立目录并在结束后清理。

## 审计校准规则（见仓库 CLAUDE.md「审计项校准」）
每条发现必须过两道验证才能上报为问题：
1. 真伪：在本仓库代码中实际复现；
2. 上游对照：TokenTracker / all-api-hub 对同一问题的真实做法
   （参考仓库在 ~/projects/reference/，以源码为准，不引用其文档结论）。
上游自身不满足的标准，不得作为 P1/P2 上报；如认为仍值得做，单独归类为
「超标建议」并给出上游依据，由项目方决定是否采纳。三种例外可正常上报：
本项目设计分歧引入的风险、多设备/hub 独有暴露面、修复成本≈0。

## 更新与构建（Windows PowerShell）
git pull
npm install        # workspaces：一并安装 dashboard 依赖
npm run build      # tsc + Vite，二者都必须产出
npm test           # 必须真实运行并输出计数（预期 {N} 全绿，不允许 0 tests）

## 逐项验收（本批变更）
{按本批修复/功能逐条列：做什么操作、预期什么结果。
 故障注入类给出明确的跨平台注入方法（参考对应测试文件），
 禁用 chmod 等 Windows 空操作手段。}

## 回归抽查（快速）
{挑 3-5 条与本批相邻的既有能力：典型如安装/卸载零残留、
 写端点 403 四连、420px 无溢出、两个注册表结束时为空。}

溢出检查口径（2026-08-08 教训）：固定应用壳下文档永不滚动，
`document.scrollWidth` 恒等于视口——必须测 `main` 容器
（`main.scrollWidth <= main.clientWidth`），且要覆盖非默认页签
（如 Skills Browse）。

## 输出格式
- 「审计发现」：每条含 优先级 / 复现步骤 / 上游对照结论（TT/AAH 怎么做的）
  / 建议修法，文件定位用 code-comment 块。
- 「超标建议」：上游不做但你认为值得的，单独列出，不占 P 级。
- 「通过项」：逐条列实测结果（测试计数、页面地址、清理确认）。
- 最后给出结论：本阶段可否关账。
````
